v12 보완: 종료 직전 늦은 블록 선택 전송 방지
- 서버 시각/경기 종료 시각/최근 16개 요청의 왕복 시간을 사용합니다.
- 응답이 오기까지 흐른 시간과 다음 요청의 왕복 여유를 포함해 종료가 임박하면 move만 보내지 않습니다.
- 조회/접속 유지 주기와 요청별 5초 제한, 오류 집계는 유지합니다.
- HTTP 400을 성공으로 바꾸거나 실패 집계에서 제외하지 않습니다.
- 모든 실패 추적 행에 오류 메시지와 moveContext(종료 시각/시각 추정/전송 여유)를 기록합니다.
- failureMessages는 저장된 일부 예시가 아닌 측정 전체 실패 메시지별 건수입니다.
- movesSkippedNearDeadline는 끝나기 직전 전송을 생략한 루프 횟수이며 실패 건수가 아닙니다.
- 이 보완은 300초 마지막 구간의 경기 종료 거절을 줄이는 목적입니다. 새 지연/실패는 그대로 기록합니다.
- 300초 시험의 서버 수집은 준비 시간까지 포함해 --seconds 600으로 실행하세요.
- 서버 업데이트/재시작은 필요하지 않습니다.

POP RUSH Windows 부하 시험 v12
고정 파일명: POP_RUSH_LoadTest_Windows.zip

GUI와 Node 실행 코드의 180초 상한을 모두 제거했습니다.
측정 시간: 1초 이상 정수 입력, 0초는 Ctrl+C로 중단할 때까지 계속 실행합니다.
인원/방 수: 별도의 제품 상한이 없습니다. 숫자는 JavaScript가 정확하게 표현하는 정수 범위입니다.
방당 2~8명은 현재 게임 API 규칙이며 총 인원/방 수 제한이 아닙니다.
오류율 5% 자동 중단은 기본 꺼짐입니다. GUI 체크박스 또는 --stop-on-errors로 켤 수 있습니다.
개별 요청의 5초 타임아웃은 실패 측정 기준으로 유지합니다. 실패해도 자동 중단을 끄면 다음 요청을 계속합니다.

ZIP 전체를 기존 Windows 폴더에 덮어쓰고 START_GUI.bat를 실행하세요.
창에 v12, 출력에 POP_RUSH_LOADTEST_VERSION=12과 실행 경로가 표시됩니다.
Node.js 24 이상 필요. GUI는 서버 추적 수집을 먼저 켜야 실행됩니다.

예시: 800명/100방/300초
node loadtest.mjs --url http://poprush.xyz --users 800 --rooms 100 --seconds 300 --mode battle --require-trace
무제한: 위 명령에서 --seconds 0 사용. 중단: Ctrl+C.
로그는 기존 logs 폴더에 UTF-8로 저장합니다. 서버 업데이트는 필요 없습니다.

중요: 서버의 진단 수집 시간은 별도입니다. 현재 서버 수집기는 최대 600초이며 이 Windows 시간 상한과는 다릅니다.
장시간 측정에서 추적 수집이 끝나도 Windows 요청은 계속됩니다.
대전은 기존처럼 5분 게임으로 생성합니다. 종료된 게임을 자동 재시작하지 않으므로 5분 이후에는 조회/접속 유지가 중심입니다.
따라서 1시간 실행을 1시간 내내 동일한 대전 부하로 해석하면 안 됩니다.
장시간 실행하면 PC의 누적 측정 데이터 메모리와 결과 파일 크기가 증가합니다.

요청 ID 왕복 확인, 오류 종류/HTTP 상태 집계, 단계별 지연/응답 크기 진단은 유지합니다.
initialTargetPass는 실패율 1% 미만, endpoint p95 500ms 미만 등의 기존 기준으로 계산합니다.
자동 중단을 끈다고 실패나 지연을 성공으로 바꾸지 않습니다.
실제 화면 렌더링/모바일 터치/음향은 API 시험에 포함되지 않습니다.

검증: 181/300/3600초 입력 및 0초 무제한 시작 후 직접 중단/결과 저장 확인.
모의 실패 응답에서 자동 중단 켜기/끄기, 잘못된 시간 입력 거절 확인.
실제 로컬 추적 API 100명/13방/5초 918건 실패0.
Windows GUI는 이 환경에서 직접 실행하지 못했으며 GUI→PowerShell→Node 입력 전달 코드를 점검했습니다.

v12 검증: 종료 시각 경계/시작 전/누락 시각/최근 RTT 16개 유지 단위 검사.
상태가 playing으로 남은 모의 종료 경기에서 종료 후 move 0건, 조회/접속 유지 계속 확인.
강제 HTTP400은 실패와 failureMessages, traceRows에 그대로 기록됨을 확인.
